# Эксплуатация

Что делать с системой после того, как она заработала: развернуть с нуля,
заводить людей, выкладывать изменения, чинить, если сломалось.

## Развёртывание с нуля

### 1. База данных

В панели Amvera создайте сервис **PostgreSQL**, тариф не ниже «Начальный».
Запомните оба адреса из карточки сервиса, они разные и оба понадобятся:

| Адрес | Вид | Для чего |
| --- | --- | --- |
| внутренний | `amvera-…-cnpg-…-rw` | приложению: оно ходит к базе из соседнего контейнера |
| внешний | оканчивается на `amvera.tech` | служебным скриптам с вашей машины, требует шифрования |

Кодировка базы должна быть **UTF8**. В логе действий встречаются стрелки и
значки, и в базе с другой кодировкой такие записи не сохраняются. Сервер
проверяет это при старте и предупреждает в логе.

### 2. Приложение

Создайте проект типа **Node.js**, тариф не ниже «Начальный». На «Пробном»
приложению с драйвером базы не хватает памяти, и это выглядит обманчиво: в
логе всё хорошо, а снаружи ошибка 503.

Источник кода — репозиторий на GitHub через вебхук либо push в git Amvera.
Конфигурация деплоя уже лежит в [`amvera.yml`](../amvera.yml), дописывать
ничего не нужно. Там же зафиксировано `singleton: true`: реплика должна быть
одна, потому что живые обновления держатся на постоянных соединениях.

Задайте переменные окружения:

```
DATABASE_URL=postgres://пользователь:пароль@внутренний-адрес:5432/имя-базы
SESSION_SECRET=длинная случайная строка
SYNC_SECRET=общий секрет с расширением
BOOTSTRAP_ADMIN=почта@example.com:ПарольДляВхода
```

Сгенерировать секреты:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

Порт в настройках приложения должен быть **3000** — тот же, что в `amvera.yml`.

### 3. Домен

Включите бесплатный домен Amvera в настройках проекта. Он выдаётся с валидным
сертификатом, и расширение сможет слать на него запросы.

### 4. Первый запуск

Запускайте сборку. В логе должно появиться:

```
[bootstrap] база пустая — раскладываю схему таблиц
[bootstrap] готово: таблиц 8, видов 10
[bootstrap] заведён администратор почта@example.com
[server] слушаю 0.0.0.0:3000, приложение из /app/public
```

Схему таблиц сервер создаёт сам, запускать ничего не надо. Войдите в
приложение и **уберите `BOOTSTRAP_ADMIN`** из переменных: пока она задана,
пароль лежит открытым текстом в настройках проекта.

### 5. Расширение

```bash
cd extension
copy config.example.js config.js
```

В `config.js` впишите адрес вида `https://ваш-домен.amvera.io/api/ingest` и тот
же `SYNC_SECRET`. Файл в репозиторий не попадает.

Проверьте на одном профиле: `chrome://extensions`, режим разработчика,
«Загрузить распакованное», папка `extension`. Откройте Ads Manager и щёлкните
по иконке расширения — в окошке будет видно, что нашлось и приняла ли база.
После проверки поставьте `debug: false` и раздайте расширение в AdsPower как
расширение по умолчанию для всех профилей.

## Люди и роли

| Роль | Что может |
| --- | --- |
| `admin` | всё: аналитика, архив таблиц, переименования |
| `manager` | правит данные, не больше десяти удалений в сутки |
| `viewer` | только чтение |

Команда заводится с вашей машины по **внешнему** адресу базы:

```bash
set DATABASE_URL=postgres://пользователь:пароль@внешний-адрес:5432/имя-базы

node server/users.js add buyer@example.com manager
node server/users.js add watcher@example.com viewer СвойПароль
node server/users.js role buyer@example.com admin
node server/users.js password buyer@example.com
node server/users.js list
node server/users.js remove buyer@example.com
```

Если пароль не указан, скрипт сгенерирует его и покажет один раз. После смены
роли человеку нужно перезайти: роль лежит в сессии.

## Обновления

**Данные и колонки — без выкладки.** Это записи в базе, а не код. Их меняют
люди прямо в приложении по своим ролям, расширение при сборе и служебные
скрипты по `DATABASE_URL`.

**Код — пушем.** Push в репозиторий Amvera или в `main` на GitHub, если
настроен вебхук. Во время сборки старая версия продолжает работать.

**Схема таблиц.** Если добавились колонки в
[`scripts/schema.js`](../scripts/schema.js):

```bash
node server/seed.js            # создать недостающее, существующее не трогать
node server/seed.js --force    # переписать описания колонок
```

Данные скрипт не трогает ни в каком режиме.

## Резервные копии

PostgreSQL в Amvera делает резервные копии по расписанию, последние три
хранятся бесплатно. Восстановление создаёт **новый** сервис с новым адресом,
после чего нужно поправить `DATABASE_URL` у приложения.

Выгрузить базу целиком можно и из приложения: «Экспорт» в панели над таблицей,
«Скачать всю базу (JSON)». Это полная копия таблиц и строк, без видов.

## Если сломалось

### Снаружи ошибка 503

Значит, прокси Amvera не достучался до приложения. Смотрите лог.

| Что в логе | Что это |
| --- | --- |
| `слушаю 0.0.0.0:3000`, дальше тишина | приложение живо, не сходится порт: проверьте настройки проекта и `containerPort` |
| строки старта повторяются по кругу | не хватает памяти, поднимите тариф |
| `SESSION_SECRET не задан` | переменные не сохранились |
| `база не отвечает` раз за разом | ошибка в `DATABASE_URL`, чаще всего внешний адрес вместо внутреннего |
| лога запуска нет вовсе | упала сборка, смотрите её вывод |

Проверить приложение снаружи, ничего не записав в базу:

```bash
curl https://ваш-домен.amvera.io/api/health
```

Ответ `{"ok":true,"db":"ok","live":N}` означает, что и сервер, и база в
порядке, а `live` показывает число открытых живых соединений.

### Расширение не шлёт данные

Щёлкните по его иконке, там будет причина.

| Что показывает | Что делать |
| --- | --- |
| «Ещё не запускался» | откройте Ads Manager; если не помогло, сценарий не совпал с адресом страницы |
| «На этой странице токен не найден» | сбор пошёл, но токена в разметке нет |
| «База не приняла секрет» | `SYNC_SECRET` в настройках приложения и в `config.js` разошлись |
| «База недоступна» | неверный адрес в `config.js` либо приложение лежит |
| «Работает» с числами | всё в порядке |

Подробный ход сбора пишется в консоль страницы при `debug: true` в `config.js`.

Проверить приёмник отдельно от расширения:

```bash
node scripts/send_test_inventory.js https://ваш-домен.amvera.io/api/ingest секрет
```

Появится аккаунт «Тестовый инвентарь» — удалите его из приложения после
проверки.

### Данные не обновляются у других вживую

Живые обновления идут по WebSocket. Если соединение не встаёт, приложение само
переходит на периодический опрос: данные обновляются медленнее, но не
застывают. Проверить, сколько соединений открыто, можно через `/api/health`.

Частая причина — несколько реплик приложения. Живые соединения раскидывает
между процессами, и правка доезжает не до всех. Реплика должна быть одна.

### В логе предупреждение про кодировку

```
[store] ВНИМАНИЕ: кодировка базы WIN1251, а нужна UTF8
```

Часть символов в такой базе не сохраняется, и записи в лог действий будут
падать с ошибкой. Лечится только пересозданием базы с кодировкой UTF8 и
переносом данных.

## Смена секретов

**`SYNC_SECRET`.** Поменяйте переменную у приложения, дождитесь пересборки,
затем обновите `config.js` расширения и раздайте его заново. В промежутке сбор
не пройдёт, данные не потеряются — расширение попробует снова.

**`SESSION_SECRET`.** После смены все текущие сессии перестают действовать,
команде придётся войти заново. Данные не затрагиваются.

**Пароль базы.** Меняется в панели Amvera, затем правится `DATABASE_URL` у
приложения.
