# Реалтайм-база FB-инвентаря

Расширение в каждом профиле AdsPower при открытии Ads Manager само собирает
FB-ассеты (БМ, кабинеты, страницы, пиксели) и шлёт их в общую базу. База —
веб-приложение: таблицы, карточки, роли, лог действий, аналитика.

```
AdsPower + расширение  ──POST──>  /api/ingest ──слияние──>  PostgreSQL
   (снимает токен,                     │                        │
    Graph API v24)                     │                  WebSocket │ живые обновления
                                       ▼                        ▼
                               один Node-процесс  ──────>  Веб-приложение
```

Всё крутится на Amvera одним приложением: оно отдаёт страницу, обслуживает её
API, держит живой канал и принимает инвентарь от расширения.

| Папка | Что это |
| --- | --- |
| `server/` | сервер: API, живые обновления, приёмник, служебные скрипты |
| `package.json` | боевые зависимости и команды; из корня их ставит сборка Amvera |
| `public/` | веб-приложение: `index.html` и слой хранилища `adapter.js` |
| `extension/` | Chrome MV3-расширение для профилей AdsPower |
| `scripts/` | схема таблиц и проверка приёмника |
| `docs/` | исходное ТЗ и принятые по нему решения |
| `firebase/` | прежний вариант на Firebase, запасной (см. его README) |
| `Realtime Sync Sources/` | входные материалы к ТЗ, оставлены как есть |

## Локальный запуск за одну команду

Ничего ставить не нужно: PostgreSQL приедет вместе с зависимостями.

```bash
npm install                 # боевые зависимости сервера
cd server && npm install    # встроенный PostgreSQL для локальной работы
cd .. && npm run dev
```

Поднимется база, создастся схема таблиц, заведётся админ, откроется
`http://127.0.0.1:3000`. Вход: `admin@local` / `admin12345`.
Данные временные; чтобы сохранялись между запусками, запусти
`node server/dev.js --keep`.

Проверить приёмник, не открывая Facebook:

```bash
node scripts/send_test_inventory.js http://127.0.0.1:3000/api/ingest dev-sync-secret
```

## Развёртывание на Amvera

### 1. База данных

В панели Amvera создай сервис **PostgreSQL**, тариф не ниже «Начальный».
Сохрани строку подключения — она понадобится приложению.

Кодировка базы должна быть **UTF8**. В логе действий встречаются стрелки и
значки, и в базе с другой кодировкой такие записи не сохраняются. Сервер
проверяет это при старте и предупреждает в логе.

### 2. Приложение

Создай проект типа **Node.js**, тариф не ниже «Начальный» — на «Пробном»
(сто мегабайт памяти) клиент PostgreSQL не поднимется, об этом предупреждает
и документация Amvera.

Реплика должна быть одна: живые обновления держатся на постоянных
WebSocket-соединениях, а закрепление клиента за репликой у Amvera
не документировано.

Конфигурация деплоя уже лежит в [`amvera.yml`](amvera.yml). В панели задай
переменные окружения:

| Переменная | Что это |
| --- | --- |
| `DATABASE_URL` | строка подключения к твоему PostgreSQL |
| `SESSION_SECRET` | длинная случайная строка, подпись сессионных cookie |
| `SYNC_SECRET` | общий секрет с расширением |

У базы в Amvera два разных адреса, и это легко перепутать. Приложению нужен
**внутренний** (вида `amvera-…-cnpg-…-rw`): оно ходит к базе из соседнего
контейнера. Служебным скриптам с твоей машины нужен **внешний** (оканчивается
на `amvera.tech`), и он требует TLS. Сервер различает их сам и включает
шифрование только там, где оно есть; при необходимости можно задать явно
переменной `PGSSL=1` или `PGSSL=0`.

Сгенерировать секреты:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

Выложи код: `git push` в репозиторий Amvera, либо настрой вебхук из GitHub,
чтобы пуш в `main` выкладывался сам.

### 3. Домен

В настройках проекта включи бесплатный домен Amvera. Он выдаётся с валидным
сертификатом, и расширение сможет слать на него запросы.

### 4. Схема таблиц

Один раз, со своей машины (строка подключения — внешняя, из панели Amvera):

```bash
set DATABASE_URL=postgres://user:pass@host:5432/db
node server/seed.js
```

Скрипт создаёт восемь таблиц с колонками и виды. Данные не трогает: повторный
запуск существующее пропускает, `--force` обновляет только описания колонок.

### 5. Команда и роли

```bash
node server/users.js add polina@example.com admin
node server/users.js add buyer@example.com manager
node server/users.js list
```

Пароль можно указать четвёртым аргументом, иначе скрипт сгенерирует и покажет
его один раз. Роли: **admin** (всё, плюс аналитика и архив таблиц),
**manager** (правит данные, не больше десяти удалений в сутки),
**viewer** (только чтение). После смены роли нужно перезайти.

### 6. Расширение

```bash
cd extension
copy config.example.js config.js
```

Впиши в `config.js` адрес вида `https://твой-домен.amvera.io/api/ingest` и тот
же секрет. Затем проверь на одном профиле: `chrome://extensions` → режим
разработчика → «Загрузить распакованное» → папка `extension`, открой Ads
Manager и посмотри, что данные долетели. С `debug: true` ход сбора виден в
консоли страницы. После проверки добавь расширение в AdsPower как расширение
по умолчанию для всех профилей.

Сбор идёт не чаще раза в час на один FB-аккаунт. Если отправка не удалась,
отметка времени не ставится и следующая вкладка попробует снова.

## Обновления после запуска

**Данные и колонки — без выкладки.** Это записи в базе, а не код. Меняются
людьми прямо в приложении по ролям, расширением при сборе и служебными
скриптами по `DATABASE_URL`.

**Код — пушем.** `git push` в репозиторий Amvera или в `main` на GitHub, если
настроен вебхук. Во время сборки старая версия продолжает работать.

## Тесты

```bash
npm test
```

Поднимает настоящий PostgreSQL из зависимостей (ни Docker, ни установленная
база не нужны), запускает сервер, заводит трёх пользователей с разными ролями
и гоняет 81 проверку: правила доступа, глубокое слияние, живые обновления
через настоящий `public/adapter.js`, приёмник инвентаря и раскладку полей.

Проверяется главное: правка одной ячейки не сносит соседние, авто-синк не
затирает логины и пароли, повторный сбор обновляет запись, а не плодит дубли.

## Безопасность

В базе лежат логины, пароли и 2FA, поэтому доступ закрыт входом и ролями, а
сессия живёт в cookie, недоступной скриптам. Расширение ключей от базы не
содержит: у него есть только адрес приёмника и общий секрет, а шлёт оно
исключительно FB-данные ассетов.

Про внутреннюю сеть Amvera: трафик между приложением и базой внутри их сети не
шифруется, об этом написано в их документации. Наружу он не выходит, но знать
об этом стоит.

Секреты задаются переменными окружения. `config.js` расширения и строки
подключения в репозиторий не коммитятся.
