# Реалтайм-база FB-инвентаря

Общая база рекламных аккаунтов Facebook для команды. Расширение стоит в каждом
профиле AdsPower: когда байер открывает Ads Manager, оно само собирает все
связанные ассеты — бизнес-менеджеры, кабинеты, страницы, пиксели со статусами,
лимитами и тратами — и отправляет их в базу. Данные появляются у всех, кто
смотрит базу, сразу, без перезагрузки страницы.

Ручное и собранное живут рядом: логины, пароли, 2FA и заметки команда
заполняет сама, а автосбор их не трогает.

**Развёрнуто:** https://pai-traffbaza-grafenters.amvera.io

## Как это устроено

```
   профиль AdsPower                    Amvera
┌──────────────────────┐      ┌────────────────────────┐
│  Ads Manager         │      │  один Node-процесс     │
│  ┌────────────────┐  │ POST │  ┌──────────────────┐  │
│  │ расширение     │──┼─────▶│  │ /api/ingest      │  │
│  │ снимает токен, │  │      │  └────────┬─────────┘  │
│  │ обходит Graph  │  │      │           ▼            │
│  └────────────────┘  │      │  ┌──────────────────┐  │      ┌────────────┐
└──────────────────────┘      │  │ слияние, upsert  │──┼─────▶│ PostgreSQL │
                              │  └────────┬─────────┘  │      └────────────┘
   браузер команды            │           ▼            │
┌──────────────────────┐ живые│  ┌──────────────────┐  │
│  веб-приложение      │◀─────┼──│ WebSocket        │  │
│  таблицы, карточки   │правки│  │ рассылка правок  │  │
└──────────────────────┘      │  └──────────────────┘  │
                              └────────────────────────┘
```

| Часть | Что делает |
| --- | --- |
| **Расширение** (`extension/`) | снимает токен на странице Ads Manager, обходит Graph API v24, шлёт инвентарь. Ключей от базы не содержит |
| **Сервер** (`server/`) | отдаёт приложение, обслуживает его API, рассылает изменения, принимает инвентарь |
| **Приложение** (`public/`) | таблицы, карточка аккаунта, дашборд, байеры, лог действий, аналитика |
| **PostgreSQL** | документы в одной таблице, содержимое в `jsonb` |

Подробнее — в [архитектуре](docs/ARCHITECTURE.md).

## Быстрый старт

Ставить PostgreSQL не нужно: он приедет вместе с зависимостями.

```bash
npm install                 # зависимости сервера
cd server && npm install    # встроенный PostgreSQL для локальной работы
cd .. && npm run dev
```

Откроется `http://127.0.0.1:3000`, вход `admin@local` / `admin12345`. Схема
таблиц создастся сама. База временная; чтобы данные жили между запусками,
запускайте `node server/dev.js --keep`.

Проверить приёмник, не открывая Facebook:

```bash
node scripts/send_test_inventory.js http://127.0.0.1:3000/api/ingest dev-sync-secret
```

## Тесты

```bash
npm test
```

92 проверки на настоящем PostgreSQL, который поднимается из зависимостей:
права по ролям, глубокое слияние, живые обновления через настоящий клиентский
слой, приёмник инвентаря, первичное наполнение базы.

Проверяется то, что ломается тише всего: правка одной ячейки не сносит
соседние, автосбор не затирает заполненные руками пароли, повторный сбор
обновляет запись, а не плодит дубли.

## Развёртывание

Разворачивается на Amvera как одно Node-приложение плюс сервис PostgreSQL.
Конфигурация деплоя лежит в [`amvera.yml`](amvera.yml), пошаговая инструкция —
в [руководстве по эксплуатации](docs/OPERATIONS.md).

Коротко: создать базу и приложение (тариф не ниже «Начальный»), задать четыре
переменные окружения, включить бесплатный домен, запушить код. Схему таблиц и
первого администратора сервер создаст сам при первом запуске.

| Переменная | Зачем |
| --- | --- |
| `DATABASE_URL` | подключение к PostgreSQL, внутренний адрес вида `…-rw` |
| `SESSION_SECRET` | подпись сессионных cookie |
| `SYNC_SECRET` | общий секрет с расширением |
| `BOOTSTRAP_ADMIN` | на один раз: `почта:пароль` первого администратора |

## Что где лежит

```
server/          сервер: API, живые обновления, приёмник, служебные скрипты
  lib/           хранилище, слияние, права, сокеты, раскладка инвентаря
  test/          сквозные тесты на встроенном PostgreSQL
public/          веб-приложение: index.html и слой хранилища adapter.js
extension/       расширение Chrome MV3 для профилей AdsPower
scripts/         схема таблиц и проверка приёмника
docs/            архитектура, эксплуатация, решения, исходное ТЗ
firebase/        прежний вариант на Firebase, запасной
```

## Безопасность

В базе лежат логины, пароли и коды двухфакторной аутентификации, поэтому она
закрыта входом по паролю и ролями, а сессия живёт в cookie, недоступной
скриптам страницы.

Расширение ключей от базы не содержит: у него есть только адрес приёмника и
общий секрет, а отправляет оно исключительно данные ассетов из Graph API,
никаких учётных данных.

Секреты задаются переменными окружения. Конфигурация расширения и строки
подключения к базе в репозиторий не попадают.
